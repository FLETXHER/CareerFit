01 / 问题背景

AI能生成内容，但不一定能帮学生做求职判断

正在摸索岗位方向的学生在找产品、运营、AI应用、设计等实习时，常见问题不是“完全不会写简历”，而是方向判断、岗位理解、证据组织和投递复盘都比较分散。为了提高匹配度，用户可能会不断改简历版本，却越来越难确认哪一版真实、清晰、适合当前岗位。

通用AI工具可以帮助生成简历表述或打招呼话术，但它不一定能回答更靠前的问题：这个岗位是否值得投？简历里哪些内容缺少证据？哪些表达存在过度包装风险？投递后该如何记录和复盘？

产品定位： 不是“自动海投工具”，而是帮助跨方向求职学生判断岗位匹配度、审查简历真实性、管理简历版本、发现作品与证据缺口、复盘投递反馈的求职决策辅助工具。

02 / 设计目标与非目标

先明确产品解决什么，也明确不做什么

设计目标

  1. 帮助用户在投递前判断岗位是否值得投。
  2. 帮助用户识别简历表述中的真实性风险。
  3. 帮助用户把岗位要求转成可补的作品 / 证据。
  4. 帮助用户记录投递版本和反馈，形成复盘。

非目标

  1. 不做一键海投。
  2. 不承诺获得offer或面试机会。
  3. 不替用户虚构经历。
  4. 不替代招聘平台。

04 / 用户痛点

求职问题分散在多个动作里，用户缺少统一判断框架

方向

岗位方向判断困难

同一段经历可以投不同岗位，但用户不清楚哪个方向更容易形成可信材料。

JD

JD看不懂，不知道匹配度

岗位描述里有很多抽象能力词，用户难以拆成具体要求和证据点。

风险

简历容易过度包装

为了贴合岗位，可能把参与、辅助、练习项目写成主导或正式发布成果。

版本

简历版本混乱

不同岗位对应多份简历，但缺少版本命名、修改原因和投递结果记录。

证据

缺少作品 / 项目证据提醒

简历写了能力点，但没有对应作品集、过程截图、文档或可复盘材料。

复盘

投递后没有复盘

投递结果、沟通反馈和简历版本没有关联，下一次修改仍然靠感觉。

06 / 竞品与替代方案简析

机会点不在替代招聘平台，而在补齐投递前后的判断链路

替代方案 优势 问题 机会点
通用AI聊天工具 生成速度快，能改写简历和话术 缺少版本记录、真实性审查和投递复盘闭环 把AI建议结构化为可检查、可追踪的求职决策过程
简历模板工具 排版成熟，适合快速生成简历 更关注呈现形式，较少判断岗位匹配和证据质量 在模板之外补充JD拆解、证据缺口和风险提示

人工求职咨询 反馈更个性化，能结合背景讨论 成本较高，质量不稳定，过程记录不一定沉淀 把常见问题产品化，先解决基础判断和材料整理问题

07 / 机会点总结

把“改写工具”往前后延伸成求职决策工具

投递前判断

先判断该不该投

现有工具更擅长改写，不擅长帮助用户判断岗位是否值得投入时间准备。

真实性边界

把润色变成可审查

现有工具容易帮用户润色表达，但缺少对过度包装和证据不足的风险提醒。

投递后复盘

记录版本、岗位和反馈

现有工具较少把简历版本、岗位要求和投递反馈关联起来，复盘难以沉淀。

08 / 用户旅程图

从发现岗位到复盘调整，每一步都需要更明确的判断依据

发现岗位

行为：浏览招聘平台、社群或内推信息。

情绪：有兴趣，但不确定是否适合。

痛点：岗位名称相似，要求差异不清楚。

机会：提取岗位方向和核心能力标签。

理解JD

行为：阅读职责、要求和加分项。

情绪：容易被专业词和能力词劝退。

痛点：不知道哪些要求是必须，哪些可补充。

机会：把JD拆成能力、经验、作品、工具四类。

判断匹配

行为：对照自己的经历和简历。

情绪：犹豫是否值得投。

痛点：缺少匹配度和缺口判断。

机会：生成“建议投 / 谨慎投 / 暂缓投”的理由。

修改简历

行为：调整项目描述、关键词和顺序。

情绪：想贴合JD，又担心写过头。

痛点：真实性边界不清楚。

机会：提示风险表述和可替代表达。

投递沟通

行为：写打招呼话术和作品集说明。

情绪：担心话术模板化。

痛点：无法强绑定岗位和自身证据。

机会：基于JD亮点生成简短、克制的沟通稿。

等待反馈

行为：等待已读、约面或无回复。

情绪：不确定问题在哪里。

痛点：没有记录投递版本和岗位差异。

机会：沉淀投递记录、使用版本和结果状态。

复盘调整

行为：根据反馈继续修改材料。

情绪：容易凭感觉反复改。

痛点：缺少可追踪的改动依据。

机会：按岗位类型复盘命中点和缺口。

09 / MVP功能设计

先解决投递前判断、材料可信和投递后记录三个核心问题

JD匹配度分析

拆解岗位要求，展示简历已有证据、弱证据和缺失项，给出是否建议投递的理由。

简历真实性审查

识别“主导、上线、负责、显著提升”等高风险表述，提醒用户补充证据或降级表达。

简历版本管理

记录不同岗位对应的简历版本、修改原因、核心关键词和投递结果。

岗位方向建议

根据经历标签和投递反馈，提示更适合优先尝试的岗位方向。

作品 / 证据缺口提醒

把岗位要求转成可准备的作品、文档、截图、复盘说明或项目材料。

打招呼话术辅助

基于岗位重点和个人证据生成简短沟通稿，避免泛泛而谈和夸张表达。

投递记录与反馈复盘

记录岗位、版本、沟通话术、结果状态和复盘结论，为下一次投递提供依据。

10 / 核心需求小样

用产品需求文档方式描述关键能力

本模块用简化PRD格式展示核心功能的用户故事、输入输出和验收标准，重点展示基础需求表达能力。

A

JD匹配度分析

需求名称：JD匹配度分析

用户故事

作为正在投递产品实习的学生，我希望系统能把JD拆成能力要求，并告诉我简历里哪些能支撑、哪些证据不足，从而判断是否值得投。

功能说明

系统将JD拆分为岗位职责、必备能力、加分项和作品要求，并与简历经历逐项对应。

输入信息

目标JD、当前简历版本、目标岗位方向。

输出结果

匹配结论、强匹配项、弱证据项、缺失项和下一步建议。

验收标准

能输出“建议投 / 谨慎投 / 暂缓投”三类结论，并说明理由；每条理由需关联至少一个JD要求或简历证据点。

B

简历真实性审查

需求名称：简历真实性审查

用户故事

作为修改简历的学生，我希望系统能识别“主导、负责、上线、显著提升”等高风险表述，并提醒我补证据或降级表达。

功能说明

系统扫描简历中的强责任、强结果和强影响表达，判断是否有证据支撑。

输入信息

简历文本、项目说明、作品链接或补充材料。

输出结果

风险表达、风险原因、风险等级、建议改法和需补证据。

验收标准

能标记风险等级，并给出更稳妥的替代表述；替代表述不得虚构经历、数据、上线状态或个人职责。

C

作品 / 证据缺口提醒

需求名称：作品 / 证据缺口提醒

用户故事

作为跨方向投递的学生，我希望系统能根据岗位要求提醒我还缺什么作品、截图、文档或复盘材料。

功能说明

系统将JD要求映射为可准备的证明材料，并按“优先补充 / 可后续补充”排序。

输入信息

目标JD、简历项目、已有作品集材料、投递方向。

输出结果

证据缺口清单、建议材料类型、补充优先级和用途说明。

验收标准

能输出至少3类证据建议，例如作品链接、过程截图、项目说明；每类建议需说明对应的JD要求。

11 / 功能优先级

P0先做能形成判断闭环的能力

优先级 功能 原因 验证方式
P0 JD匹配度分析 直接帮助用户判断岗位是否值得投 观察用户是否能在10分钟内形成投递判断
P0 简历真实性审查 降低过度包装和不可验证表达风险 统计风险项识别数量与用户修改情况
P0 作品 / 证据缺口提醒 让简历建议落到可补充材料上 观察用户是否补充作品、截图或项目说明
P0 投递记录 为后续复盘提供基础数据 查看投递记录完整率
P1 简历版本管理 减少版本混乱，和投递结果建立关联 观察用户是否按岗位维护版本说明
P1 打招呼话术辅助 提升沟通材料和岗位的绑定程度 观察用户是否采用或二次编辑话术
P1 岗位方向建议 在有一定记录后，帮助用户收敛方向 观察后续投递岗位类型是否更集中
P2 长期求职数据趋势 需要较多记录后才有意义 观察多周投递和反馈变化
P2 同类岗位推荐 依赖岗位库和推荐策略，MVP阶段成本较高 验证推荐岗位的打开和投递意愿
P2 面试问题预测 属于投递后延伸场景，优先级低于投递判断 验证面试准备时的使用频率

15 / 项目总结

这个项目展示的是产品思考过程，而不是虚构外部成果

CareerFit的核心价值在于把“看到岗位后该怎么判断、怎么改材料、如何避免过度包装、投递后如何复盘”整理成一个连续的产品流程。对作品集来说，它更适合展示需求拆解和MVP规划能力，而不是强调复杂算法或外部成效。

本项目没有试图证明我已经具备完整产品经理能力，而是用于展示我对真实问题的拆解、基础需求表达、MVP优先级判断和低保真原型表达能力。

  • 真实问题拆解：从个人求职痛点出发，拆成方向、JD、证据、版本和复盘问题。
  • 用户流程分析：明确从发现岗位到复盘调整的关键断点。
  • MVP功能规划：优先解决投递前判断、真实性审查和记录闭环。
  • 需求优先级判断：用P0/P1/P2区分短期必要功能和后续扩展能力。
  • 低保真原型表达：用简单线框表达页面结构和核心信息流。
  • AI工具辅助产品分析：把AI用于结构化判断和风险提示，而不是替代用户做决定。
